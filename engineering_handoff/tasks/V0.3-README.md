## 3. Sprint 排期建议（2 人 × 3 sprint）

### Sprint 1（2 周）· 地基

| 工程师 A（后端） | 工程师 B（后端 + 全栈） |
|---|---|
| T16 DB Schema | T17 Connector ABC |
| T18 飞书 OAuth | T22 Retention（先写空骨架） |
| T19 历史消息 + Webhook（启动） | T23 API（OpenAPI schema 先行） |

**Sprint 1 结束验收**：
- 飞书 OAuth 完整跑通（含 token 刷新）
- 测试群发消息能进 redis channel
- T23 OpenAPI 文档完整，前端可同步开工

### Sprint 2（2 周）· 信号 + UI 启动

| 工程师 A | 工程师 B |
|---|---|
| T20 SignalGate（规则 + Ollama 集成） | T24 Wizard UI（基于 T23 OpenAPI） |
| T21 ValueSegment 组装 | T25 Chat UI 静态版（无 SSE） |
| T19 收尾（Webhook 验签 + 错误处理） | T22 Retention 完整实现 |

**Sprint 2 结束验收**：
- 端到端：用户发消息 → SignalGate → ValueSegment 入库
- 前端 UI 静态版可点（用 MSW mock）
- 100 条 fixture 上 SignalGate 准确率 ≥ 85%

### Sprint 3（2 周）· 端到端打磨 + 试点准备

| 工程师 A | 工程师 B |
|---|---|
| 接入 MVP 现有蒸馏管线（生成 Skill） | T25 SSE 实时更新 |
| 试点环境部署 + 监控 | UI 打磨 + EmptyState/ErrorState |
| 100 条真实消息蒸馏调优 | 准入材料：邀请文案 + 同意书 |

**Sprint 3 结束验收**：
- 5 家试点企业（已签 NDA）正式接入
- 蒸馏延迟实测 < 5 分钟（实时） / < 24h（回填）
- 至少 1 个真实 Skill 经试点用户审核发布

## 4. 验收标准（v0.3.0 整体 Done）

| 维度 | 标准 |
|---|---|
| 试点企业 | 5 家飞书企业接入 30 天，留存 ≥ 80% |
| SignalGate | 人工抽样 100 条，误判率 < 15% |
| 蒸馏延迟 | 实时 P95 < 5 min；历史回填 < 24h |
| 数据合规 | 90 天到期清理 cron 验证通过；撤回流程 30 天物理删除验证通过 |
| 单测覆盖率 | 后端 ≥ 80%；前端 ≥ 70% |
| 端到端 | 一个 5 步用户旅程（添加→授权→邀请 bot→等待→查看 Skill）完成耗时 < 15 分钟 |
