## 2. 依赖图

```
v0.5.0 (M5 @ 机器人按需):
T45 (parse) ─→ T46 (dispatch) ─→ T47 (thread reply)
              │
              └─→ 复用 v0.4 dispatcher.fire 现有管线

v0.5.1 (Q5 contributor 同意):
T48 (schema) ─→ T49 (notifier) ─→ T50 (endpoints + sweep)
                                  │
                                  └─→ T51 (前端 UI)

模块 A (v0.5.0) 和 模块 B (v0.5.1) 之间**无相互依赖**, 可完全并行启动.
```

**关键路径**:
- v0.5.0: T45 → T46 → T47（3 步串）
- v0.5.1: T48 → T49 / T50（T49 和 T50 可并行）→ T51

## 3. Sprint 排期建议

### Sprint 1（2 周）· 双模块同时启动
- 工程师 A：T45（解析 + 限频）+ T48（schema 扩展）→ 都是基础设施类，1 sprint 能搞完
- 工程师 B：调研 + 起 T49 通知模板（飞书 interactive card 验证）

### Sprint 2（2 周）· 主要后端
- 工程师 A：T46 MentionDispatcher（3 家 IM connector 加 hook）
- 工程师 B：T49 ConsentNotifier 完成 + T50 endpoint 启动

### Sprint 3（2 周）· 收尾
- 工程师 A：T47 thread 回复 3 家
- 工程师 B：T50 sweep + T51 前端启动

### Sprint 4（2 周）· 前端 + 端到端
- 工程师 B：T51 完成
- 联合：v0.5.0 真实模拟 / v0.5.1 多 contributor 集成

> 紧 4 sprint = 8 周；松 5-6 sprint 含 buffer。

## 6. 不在范围（v0.5 不做）

- 跨企业 contributor IM DM（v0.5 仅同企业内通知）
- 自定义时间窗（非 5 预设）（OD-4 故意限制）
- 私聊 @ 触发（仅群消息）
- SSE 撤回通知前端切换（v0.5.x）
- LLM 真账单接入（v0.5.2 单独做）
- contributor 拒绝后的 SignalGate 负样本训练（v0.6+）
