### 0.2 通用规范

#### 组件库

- **shadcn/ui + Tailwind**（前端实现锁定，设计师以此为参考）
- 图标：lucide-react
- 编辑器：TipTap（富文本 + 自定义节点：证据徽章、脱敏占位、callout）

#### 设计 token 建议

| token | 用途 |
| --- | --- |
| 主色 | sky-600 / blue-700（参考 BRD 标识体系，正式由品牌系统定） |
| 警告色 | amber-500（脱敏未确认 / 自评分低） |
| 错误色 | red-600 |
| 成功色 | emerald-600 |
| 中性灰 | slate-50/100/300/500/700/900 |
| 字体 | Inter / 系统字体回退；中文 PingFang / 思源 |
| 圆角 | 6px (按钮) / 8px (卡片) / 12px (面板) |
| 间距 | 4 / 8 / 12 / 16 / 24 / 32 / 48（4 倍数） |

#### 通用状态命名

每个核心页面必须设计以下状态：

- `loading` · 骨架屏 + 进度提示
- `empty` · 空态插画 + 引导 CTA
- `error` · 错误信息 + 重试 / 报告反馈
- `success` · 完成确认 + 后续 CTA
- `disabled` · 灰显 + 悬浮解释（如"发布按钮禁用，还有 N 处敏感未确认"）
- `partial` · 部分完成（如生成中、审批中）

#### 响应式

- MVP 仅做桌面端（≥ 1280px 宽）的高保真
- 移动端只做"阅读"视图（不可编辑），低优先级
- 平板可以借用桌面端布局

#### 无障碍基线

- WCAG 2.1 AA 色对比 ≥ 4.5
- 关键操作均有键盘快捷键（设计上预留位）
- 所有图标与图片提供 alt 文本

## T01 · 认证流程

**优先级**：P0 · **估时**：2 天 · **关联 PRD**：§4.1 / §6.2

### 目的

让用户在 5 分钟内完成"注册 → 邮箱验证 → 创建第一个项目"。设计上要明确"这是私有化部署的实例，不是 SaaS 注册"。

### 包含子页面

- **T01.1 注册页** · 邮箱 + 密码 + 显示名 + 同意条款
- **T01.2 登录页** · 邮箱 + 密码 + "忘记密码"
- **T01.3 邮箱验证** · 等待 / 已验证 / 重发邮件
- **T01.4 找回密码** · 邮箱 → 新密码

### 关键 UI 元素

- 顶栏：**TokenKnows 实例信息**（实例地址 + 版本号 + 健康指示灯）始终可见（呼应要素 #2）
- 注册表单：邮箱 / 密码（强度指示器）/ 显示名 / 服务条款勾选
- 密码强度规则气泡：≥ 10 位、含字母 + 数字 + 符号
- 错误信息：行内 inline + 提交后整体
- 注册成功 → 直接跳"创建项目"（无中间欢迎页，呼应要素 #1）

### 状态机

- `loading` · 提交中骨架
- `error` · 邮箱已存在 / 密码强度不足 / 网络错误（每种独立文案）
- `locked` · 5 次失败锁定 15 分钟，剩余时间倒计时
- `email-pending` · 邮箱待验证 + 重发按钮（60s 冷却）

### 交互注解

- 密码输入框右侧"眼睛"切换明文/掩码
- 邮箱输入失焦时格式校验
- 服务条款 / 隐私政策可点击展开 modal

### 验收标准

- [ ] 桌面端 1280-1920px 自适应
- [ ] 全部状态完成 Hi-Fi
- [ ] 实例信息常驻顶栏显示正确（不同状态：健康 / 异常）
- [ ] 移动端阅读视图（响应式简版）

## T02 · 项目创建 + 数据源向导

**优先级**：P0 · **估时**：3 天 · **关联 PRD**：§4.1 / §5.1

### 目的

让用户在创建项目后立刻看到 4 个数据源卡片，并能在每张卡片内完成"接入 → 看到连接状态"的闭环。

### 包含子页面

- **T02.1 项目创建表单**（项目名 + 默认 Owner + 模板推荐位）
- **T02.2 数据源卡片视图** · 4 张卡片（Claude Code / Cursor / VS Code / GitHub）
- **T02.3 Claude Code 接入向导** · 3 步（下载链接 → 安装命令 → 自动注入连接 token）
- **T02.4 Cursor / VS Code 接入向导** · 类似 Claude Code，但下载链接不同
- **T02.5 GitHub 接入向导** · PAT 输入 + 仓库多选 + 权限校验

### 关键 UI 元素

- 项目创建：
  - 必填仅"项目名"
  - Owner 默认本人（可改）
  - 下方"推荐模板"卡片位（呼应要素 #5，不强制）
- 数据源卡片：
  - 卡片头：图标 + 数据源名称
  - 状态徽标：未配置 / 已连接 / 失败 / 配置中（颜色区分）
  - 操作按钮：连接 / 重连 / 详情
- 接入向导：
  - 步骤指示器（1 → 2 → 3）
  - 复制按钮（命令 / token 一键复制）
  - 实时状态反馈（"等待插件首次连接..."→"已连接 · 检测到 N 个会话"）

### 状态机

每张数据源卡片：

- `not_configured` · 空态，"+ 连接"按钮
- `configuring` · 配置中（向导打开）
- `pending_connection` · 等待客户端首次握手
- `connected` · 已连接，显示最近事件数
- `failed` · 失败 + 错误详情 + 重试按钮
- `paused` · 用户手动暂停

### 交互注解

- 卡片点击展开向导（slide-in 或 modal）
- 错误状态下点击"详情"展开错误原因 + 故障诊断指引
- PAT 输入框：输入后行内验证权限（`repo:read / pull_requests:read / issues:read`），缺失权限显式列出

### 验收标准

- [ ] 4 种数据源向导 Hi-Fi
- [ ] 所有连接状态都有 Hi-Fi 设计
- [ ] 失败场景的诊断指引文案与 UI

## T03 · 工作台首页

**优先级**：P0 · **估时**：3 天 · **关联 PRD**：§8.1

### 目的

让用户每天打开 TokenKnows 第一眼就感受到"数据在流"。三层结构：项目卡 / 事件流 / 待办。

### 关键 UI 元素

- **顶栏**：实例信息（地址 / 版本 / 健康）+ 项目选择器 + 用户头像
- **左侧导航**：概览 / 事件流 / 文档 / 数据源 / 模板 / 团队 / 设置
- **右侧抽屉**（可折叠）：通知 + 待办
- **主区**（三层）：
  1. **顶部项目卡**：项目名 / 4 种数据源连接状态 / 4 类资产数量 / 近 7 日活跃度
  2. **中部实时事件流**：最近 50 条事件
     - 每条：来源图标 + 标题 + 作者 + 时间 + 类型徽标 + trust_score 颜色条
     - 可按"来源 / 作者 / 类型"筛选（左侧侧栏 facet）
  3. **底部本周待办**：待审 / 待生成 / 待发布（按类型分组）

### 状态机

- 项目卡：`fully_connected` / `partially_connected`（有失败源 → 卡片右上角警告徽标）
- 事件流：`empty`（无事件，引导用户去配数据源）/ `streaming`（实时滚动）/ `paused`
- 待办：`empty`（空态 + 创建文档 CTA）/ `has_items`

### 交互注解

- 实时事件流默认按 occurred_at 倒序
- 新事件流入时**淡入动画**（不打扰但可感知）
- 事件条点击展开 → 触发 T04 详情面板
- 顶栏实例信息悬浮 → tooltip 显示版本号、健康状态明细、license 剩余天数
- "+ 新建文档" CTA 始终右上角悬浮

### 验收标准

- [ ] 3 种数据规模（5 / 50 / 500 事件）下的布局表现
- [ ] 多数据源时的视觉密度可控
- [ ] 顶栏实例信息在不同窗口宽度下的折叠策略

## T06 · 文档生成结果页（核心）

**优先级**：P0 · **估时**：5 天 · **关联 PRD**：§4.2 / §8.2

### 目的

**全产品最关键页面**。承担"展示生成结果 + 编辑 + 自评 + 重生成 + 证据查看 + 提交审核"完整链路。

### 关键 UI 元素

**整体布局**

```
┌──────────────────────────────────────────────────────┐
│ 顶部：标题 · 类型徽标 · 版本 · 状态 · 自评卡         │
├──────────────────────────────────────┬─────────────┤
│ 主区域                                │ 右侧抽屉    │
│  - 章节导航（左侧浮窗）                │ 证据链      │
│  - 文档预览 / 编辑                     │ 评论        │
│                                       │ 历史版本    │
├──────────────────────────────────────┴─────────────┤
│ 底部操作条：保存 · 重生成 · 切模型 · 提审 · 导出 · 发布 │
└──────────────────────────────────────────────────────┘
```

**顶部自评卡**：4 项指标（覆盖度 / 引用密度 / 空话比例 / 与历史相似度），每项配颜色（绿 / 黄 / 红）

**章节导航**（左侧浮窗）

- 章节列表（标题 + 状态徽标 + 当前编辑指示）
- 当前章节高亮
- 可拖拽排序（如果不锁结构）

**文档编辑区**

- TipTap 富文本编辑器
- 每段右上角浮出「📎 N 条来源」徽章（触发 T07 抽屉）
- 每章节右上角浮出"…"菜单：重生成 / 切换模型 / 编辑要求 / 删除
- 章节左侧小标：来自哪个模型生成（Claude / GPT / Ollama-Qwen 等）
- 自评分低的章节顶部 inline 警告条（标红 + 浮窗"建议补充数据源后重生成"）

**底部操作条**（粘性）

- 自动保存指示（5 秒一次）
- 主操作：保存 · 重生成 · 切模型 · 提交审核 · 导出 · 发布

### 状态机

- `loading` · 文档生成中（5 阶段进度条：采集 → 识别 → 抽取 → 撰写 → 校对）
- `draft` / `in_review` / `approved` / `published` / `archived`
- 单章节：`pending` / `generating` / `ready` / `regenerating` / `failed`
- 多人编辑：`locked_by_other`（显示"X 正在编辑"）

### 交互注解

- 鼠标悬停章节标题 → 浮出操作菜单
- 章节级"重生成"点击 → T08 对话框
- 段落右侧「📎」点击 → T07 抽屉滑出
- 编辑文本后自动保存指示从"已保存"→"保存中..."→"已保存"
- 自评分低章节默认折叠"警告条"，hover 展开建议
- 底部"发布"按钮：脱敏未全部确认时**灰显**，悬浮 tooltip"还有 N 处敏感未确认"（要素 #13）

### 关键设计挑战

1. **页面信息密度极高**：要在不拥挤的前提下展示自评卡 / 章节导航 / 内容 / 证据链 / 评论 / 操作条
2. **章节级状态可视化**：不同章节可能处于不同状态（已批 / 待审 / 重生成中）
3. **生成进度可视化**：5 阶段进度需要有趣味、有节奏感（呼应要素 #8）

### 验收标准

- [ ] 文档生成中 + 渲染完成 + 部分章节重生成中 三种状态都有 Hi-Fi
- [ ] 自评卡四种颜色档位
- [ ] 多人编辑（锁定）状态
- [ ] 失败章节状态（生成失败 + 重试入口）
- [ ] 移动端阅读视图（不可编辑）

## T07 · 证据链抽屉

**优先级**：P0 · **估时**：2 天 · **关联 PRD**：§5.4 D2 / §8.3

### 目的

让用户点击「📎」一键看到这段是从哪些 PR / 对话 / 文件来的。

### 关键 UI 元素

- 抽屉式（右侧 480-560px 宽）
- 顶部：当前章节段落预览 + 总来源数 + 排序选项（按 trust_score / 时间）
- 来源卡列表：
  - 顶部行：来源图标 + 类型徽标 + 作者 + 时间
  - 中部：被引用 span 的原文片段（高亮）
  - 底部：trust_score 显示（4 因素分解 tooltip）+ 操作（"在事件流中查看" / "在源头打开" / "标记 stale"）
- 底部："+ 手动添加来源"按钮（弹出事件搜索）

### 状态机

- `loaded` / `empty`（未引用源，显示警告 + "需要补充来源" CTA）
- `redacted`（来源被脱敏，普通角色看到遮蔽；Reviewer / Owner 可"临时展开原文"按钮，展开入审计）

### 交互注解

- 来源卡 hover 时 → 主文档区段落高亮（双向联动）
- 点击"在源头打开"→ 新标签页打开外部 URL；本地文件来源显示路径
- trust_score 点击展开 → 显示分解：source_authority / corroboration / recency / extraction_confidence

### 验收标准

- [ ] 3 种来源类型（GitHub / IDE 对话 / 本地文件）的卡片样式
- [ ] 脱敏遮蔽状态 + "临时展开"交互
- [ ] 单段 > 20 来源时的折叠展示（top 10 + "+N more"）

## T08 · 章节重生成 / 切换模型对话框

### 验收标准

- [ ] 自然语言指令输入框示例提示

## T09 · Reviewer 审批视图

**优先级**：P0 · **估时**：3 天 · **关联 PRD**：§4.3 / §5.5 / §8.4

### 目的

让 Reviewer 在网页内完成所有审批，不需要切到外部工具。

### 关键 UI 元素

**整体布局**

```
┌──────────────────────────────────────────────────────┐
│ 顶部：审批进度（N/M 章节已 approve）· 全部通过/驳回   │
├────────┬────────────────────────────┬─────────────┤
│ 章节   │ 文档主区                    │ 评论侧栏   │
│ 列表   │ - 与编辑视图一致            │ - 行级     │
│ 状态   │ - 段落右侧"批注"图标        │ - 章节级   │
│        │                              │ - 文档级   │
└────────┴────────────────────────────┴─────────────┘
```

**章节列表**

- 每章节状态徽标（pending / approved / rejected）+ 批注数
- 章节级三按钮：approve / reject / comment

**评论侧栏**

- 三层 tab：行级 / 章节级 / 文档级
- 每条评论：作者 + 时间 + 内容 + 解决 / 未解决状态

### 状态机

- 整体：`in_review` / `approved`（全部通过 + 脱敏全确认）/ `rejected`（任一章节驳回）
- 章节：`pending` / `approved` / `rejected`
- 评论：`open` / `resolved`

### 交互注解

- 段落 hover 时浮出"批注"图标
- 章节通过 / 驳回需附评论（驳回必填）
- "全部通过"按钮：所有章节一键 approve（仍需补评论）
- "全部驳回"按钮：一键 reject 全部章节（必填整体评论）

### 验收标准

- [ ] 大文档（10+ 章节）的章节列表滚动表现
- [ ] 多 Reviewer 同时审批的协作显示
- [ ] 已审批 vs 待审批 的视觉对比

## T10 · 脱敏确认面板

**优先级**：P0 · **估时**：2 天 · **关联 PRD**：§5.6 / §4.3

### 目的

让用户**一目了然地**看到所有敏感识别，逐项决定怎么处理。

### 关键 UI 元素

- 顶部："还有 N 处敏感信息未确认 · 全部应用建议 / 逐项处理"
- 列表：每个识别项一行
  - 类型徽标（CUSTOMER / API_KEY / INTERNAL_SYSTEM / 自定义）
  - 原文片段（脱敏前；只在 Reviewer 视图可见）
  - 建议替换：占位符 / 用户自定义
  - 操作：应用 / 标记为非敏感 / 自定义文本
- 底部："一键应用所有建议"按钮 / "取消"

### 状态机

- 每项：`pending` / `confirmed`（已应用）/ `overridden`（自定义文本）/ `exempted`（标记非敏感）

### 交互注解

- 单项 hover → 主文档对应位置高亮
- "标记为非敏感"二次确认（避免误操作）

### 验收标准

- [ ] 类型徽标的色彩 / 图标系统

### 附录 B · 错误状态设计原则

- 永远给出 1 句"为什么"（用户可理解的语言）+ 1 个具体行动建议
- 系统类错误（5xx）展示报告按钮（一键反馈到工单）
- 用户类错误（权限不足、配置缺失）直接给出修复入口

### 附录 C · 空状态设计原则

- 不只画"空状态插画"，必有"下一步该做什么"的明确 CTA
- 引导文案不超过 2 行
- 示例："还没有事件，去[添加数据源]让 TokenKnows 开始记录你的研发过程"
