## 1. 飞书开放平台准备

### 1.1 创建 / 选择应用

进入 [飞书开放平台](https://open.feishu.cn/app)，选择"企业自建应用"（**不要选商店应用**）。

记录以下凭据（"凭证与基础信息"页）：

| 字段 | env 变量 | 示例 |
|---|---|---|
| App ID | `FEISHU_APP_ID` | `cli_a1b2c3d4e5` |
| App Secret | `FEISHU_APP_SECRET` | `Xxxxxx...32 字符xxxx` |
| Encrypt Key | `FEISHU_ENCRYPT_KEY` | 自定义随机串, ≥ 16 字符 |
| Verification Token | `FEISHU_VERIFICATION_TOKEN` | 飞书自动生成 (本 MVP 暂不强校验) |

### 1.2 开启权限

进入"权限管理" → 申请以下 scope（**必须全部勾选,否则消息拉不到**）：

- `im:message`             读取与发送单聊、群组消息
- `im:chat:readonly`       获取群组信息
- `im:chat`                获取群组成员
- `contact:user.id:readonly`  获取用户 user_id

→ 点击"申请版本",由企业管理员审批通过后方可生效。

### 1.3 配置 OAuth 回调 URL

进入"安全设置" → "重定向 URL":

```
https://YOUR-DOMAIN.com/api/v1/webhooks/feishu/auth-callback
```

⚠️ **必须 HTTPS**，飞书拒绝 HTTP。

### 1.4 配置 Event Subscription Webhook

进入"事件订阅" → "请求网址 URL":

```
https://YOUR-DOMAIN.com/api/v1/webhooks/feishu/events/{tenant_key}
```

> ⚠️ 此处 `{tenant_key}` 是飞书 placeholder，**保持字面量** "tenant_key"。
> 真实 tenant_key 由飞书在每次请求 URL 时动态替换为企业 ID。

→ 点击"验证"按钮，飞书会发起一次 `url_verification` 请求。
若返回 `200 + {"challenge": "xxx"}` 则验证成功。

订阅事件列表勾选：
- `im.message.receive_v1` (消息接收)

## 2. 后端配置 (`.env`)

复制 `.env.example` → `.env`，填入以下变量（**全部必填**）：

```bash
# ─── v0.3 IM 集成 (必填) ──────────────────────────────────────

# OAuth token 加密主密钥 (Fernet)
# 生成: python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
IM_ENCRYPTION_KEY=ZmVybmV0LWtleS1zaGFsbC1iZS0zMi1ieXRlcw==

# 飞书应用凭据 (1.1 节获取)
FEISHU_APP_ID=cli_xxxxxxxxx
FEISHU_APP_SECRET=xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
FEISHU_ENCRYPT_KEY=your-encrypt-key-at-least-16-chars
FEISHU_VERIFICATION_TOKEN=飞书自动生成的-token

# OAuth callback URL (与 1.3 节飞书后台配置完全一致)
FEISHU_OAUTH_REDIRECT_URI=https://YOUR-DOMAIN.com/api/v1/webhooks/feishu/auth-callback

# 飞书 API base
#   国内版: https://open.feishu.cn (默认)
#   国际 Lark 版: https://open.larksuite.com
FEISHU_API_BASE=https://open.feishu.cn

# ─── 现有 (V0.2 已配置, 此处仅提醒检查) ─────────────────────
ANTHROPIC_API_KEY=sk-ant-xxx
INSTANCE_EGRESS_ENABLED=true
DEFAULT_PROJECT_EGRESS_ENABLED=true
```

> 🔑 **关键安全约束**：
> - `IM_ENCRYPTION_KEY` 一旦确定**不能换**。换了之后旧 connection 的 token 永远解不出来,只能让所有用户重新 OAuth.
> - `FEISHU_APP_SECRET` / `FEISHU_ENCRYPT_KEY` 不能进 git。生产用 KMS / Vault 注入.

## 3. 启动后端

```bash
cd code/tokenknows-api
pip install -e ".[dev]"
uvicorn app.main:app --host 0.0.0.0 --port 8001 --workers 1
```

> ⚠️ **生产 workers 必须 = 1** (MVP 用单进程内存 cache; 多 worker 会导致 IM connection cache 不同步).
> 真要多实例时换成 Redis cache, 留 v0.4.

**启动后立刻检查的日志行** (按出现顺序):

```
[info] tokenknows_api_starting   version=...   environment=production
[info] persistence_initialized   path=./data/state.sqlite
[info] skills_bootstrapped        count=N
[info] im_connections_bootstrapped count=M
[info] im_retention_sweep_started  interval_seconds=3600
```

最后一行必须出现 — 缺失则 retention 任务未启动 (90 天后消息不会自动清, 合规出问题).

## 4. 真接入冒烟测试 (推荐 staging 先跑一遍)

### 4.1 健康检查

```bash
curl -fsS https://YOUR-DOMAIN.com/api/v1/health
# 期望: 200 + {"ok": true}
```

### 4.2 Webhook url_verification

在飞书后台"事件订阅"页点"验证"按钮。期望日志:

```
POST /webhooks/feishu/events/tenant_key  200
```

### 4.3 OAuth 全链路

打开浏览器→ `https://YOUR-DOMAIN.com/projects/proj-demo-001/datasources` → 点 "添加 IM" → 选飞书 → "获取授权链接" → 跳到飞书页 → 完成授权 → 自动跳回 → connection.status 变 `active`。

日志期望:
```
[info] im_connection_created    id=im-xxx platform=feishu
[info] feishu_oauth_callback_ok connection_id=im-xxx tenant=YOUR_TENANT_KEY
[info] im_oauth_applied         id=im-xxx tenant=YOUR_TENANT_KEY
```

### 4.4 群管理 + 真接消息

进 `/datasources/im/connections/{cid}/chats` → 应能看到飞书群列表 → 选一个群 → 点 "邀请 bot 入群" → 飞书会发系统消息提示 bot 已加入。

然后在群里**发一条决策消息** (e.g. "我们决定使用 pgvector"):

后端日志期望:
```
[info] feishu_webhook_message_stored
       connection=im-xxx chat=oc_xxx msg=om_xxx is_signal=True new=True
```

> 若 `new=False` 表示该 msg_id 已存在 (幂等保护). 若 `is_signal=False` 但消息明显有价值,可能是 R10 启发式判断失误,后续 v0.3.1 接 Qwen2.5-3B 改善.

### 4.5 蒸馏 → Skill

在 chat 详情页点 "触发蒸馏",期望返:

```json
{"segments_persisted": N, "segment_ids": ["seg-xxx", ...]}
```

进 `/projects/.../skills` 应能看到从 IM 蒸馏出的新 skill (status=draft).

### 4.6 Retention 验证 (可选, 时间长)

短期验证:

```bash
# 注入一条假消息 retention_until=now-1d
sqlite3 ./data/state.sqlite <<SQL
UPDATE im_messages
SET retention_until = '2025-01-01T00:00:00+00:00'
WHERE id = (SELECT id FROM im_messages LIMIT 1);
SQL

# 等下一次 retention_sweep_loop (最多 1 小时), 或调小 _RETENTION_SWEEP_INTERVAL_SECONDS
# 验证消息 content 已替换为占位符
sqlite3 ./data/state.sqlite "SELECT content FROM im_messages WHERE redacted=1 LIMIT 1;"
# 期望: [message retention expired]
```

## 5. 撤回流程演练

### 5.1 用户撤回授权

前端: 进 `/datasources` → 点连接卡片"撤回"按钮.
后端期望:
```
[info] im_connection_revoked id=im-xxx grace_until=2026-06-21T...
```

connection.status 变 `revoked`,但消息**还在保留**,等 30 天宽限期.

### 5.2 强制清理 (运维触发)

宽限期后调:
```python
# Python REPL 或脚本
from app.services.im.retention import force_purge_revoked_connection
result = force_purge_revoked_connection("im-xxx")
print(result)  # {"messages_redacted": N, "messages_total": M}
```

## 6. 监控告警

最低限度监控以下日志关键字 (e.g. Loki / ELK):

| 关键字 | 含义 | 处置 |
|---|---|---|
| `feishu_webhook_signature_mismatch` | 收到伪造请求 | 排查 FEISHU_ENCRYPT_KEY 配置 |
| `feishu_webhook_decrypt_failed` | 解密失败 | 同上 |
| `feishu_oauth_callback_exchange_failed` | code 兑换失败 | 一般是用户取消;频发查 app_secret |
| `im_retention_sweep_failed` | 后台清理出错 | 立即 alarm, 合规风险 |
| `im_force_purge_redact_failed` | 撤回清理失败 | 立即 alarm |

## 7. 已知限制 (v0.3.0)

如下功能 v0.3.1+ 才补齐,部署时务必告知用户:

1. **R10 SignalGate 启发式** — 长文 ≥100 字标 signal, 否则 noise. 误判较多, 可能漏掉短而高价值的消息. v0.3.1 接 Qwen2.5-3B 本地分类器.
2. **distill 同步** — 单 chat 蒸馏 ~30s, 大群 (>500 消息) 可能 timeout. v0.3.1 改异步 + SSE.
3. **个人微信不支持** — 协议封禁风险, 永久不接入. 企微 / 钉钉留 v0.4.
4. **多实例不支持** — workers=1 限制. v0.4 接 Redis cache.
5. **同意书签字流程未实施** — 当前仅记录 consent_signed_by/user_id 字段, UI 流程留 v0.3.1.
6. **token 自动刷新无定时器** — access_token 过期时业务调用会抛 401 让用户重连. 自动后台刷新留 v0.3.1.

## 附录 A · 故障排查 FAQ

**Q1: `feishu_webhook_signature_mismatch` 一直报**

- 检查 `FEISHU_ENCRYPT_KEY` 与飞书后台一致
- 检查反向代理 (nginx) 是否改了 body (gzip 等会破坏签名)
- 在 nginx 配置中加 `proxy_request_buffering off` 保证原文透传

**Q2: `OAuth callback 跳回时 connection 标 revoked`**

- code 过期 (飞书 code 有效期 5 分钟,用户超时点了"同意"会过期)
- redirect_uri 与飞书后台不一致 (注意末尾斜杠)
- 让用户重新走 OAuth

**Q3: `im_connections_bootstrapped count=0 但 SQLite 表里有数据`**

- 加密密钥换了,旧 connection 解密失败被跳过. 看 `im_connection_parse_failed` 日志验证.
- 唯一恢复方案:让用户重新走 OAuth.
